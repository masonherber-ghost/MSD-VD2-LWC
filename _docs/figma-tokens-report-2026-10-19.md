## 3. Set up incorrectly in Figma

### 3.1 Border widths: values shifted down a step

| Variable | Label says | Value | SLDS ships |
|---|---|---|---|
| `sizing-border/1 (1px)` | 1px | 1 | 1px |
| `sizing-border/2 (2px)` | 2px | **1.5** | 2px |
| `sizing-border/3 (2px)` | **2px** | 2 | 3px |
| `sizing-border/4 (4px)` | 4px | **3** | 4px |

- **What it looks like:** a slip. The values look shifted down by one step, and `/3`'s label repeats `/2`'s.
- **What it breaks:** imported as Figma has them, every component that uses a 2px border (focus rings drawn as borders, selected states, the 2px button border in the button review) renders at **1.5px**. Every 3px border renders at 2px.
- **Fix:** set the values to 1 / 2 / 3 / 4 and the labels to match.
- **Why it's imported anyway:** this import writes Figma's values as instructed, so these are live now. That's the first thing to correct, in Figma or with a decision to override.

### 3.2 `error-base/100 (Pink 100)` exports as `--slds-g-color-error-base-95`

- **What it breaks:** on export it **overwrites step 95** (`#faebeb`) with white.
- **How the import handles it:** it writes the variable to `--slds-g-color-error-base-100`, the step in its name.
- **Fix:** set the code syntax to `--slds-g-color-error-base-100`.

### 3.3 Palette steps 35, 85, 5: still exporting another step's name (24 variables)

Unchanged from the 15th:
- every palette's `/35` exports `…-40`
- every palette's `/5` exports `…-10`
- every palette's `/85` exports `…-90`, except cloud-blue, whose `/85` has no code syntax

SLDS has no 35, 85 or 5 palette steps. **What it breaks:** an export overwrites steps 40, 90 and 10 with the wrong colour. The import skips these 24; nothing aliases them. **Fix:** clear their code syntax.

### 3.4 `font/scale/base` exports `--slds-g-font-size-base`

Unchanged. In SLDS that name is an alias **of** `--slds-g-font-scale-base`, so setting it doesn't move the step it points at. The import writes `--slds-g-font-scale-base`. **Fix:** change the code syntax.

### Method

- The snapshot was read with the skill's step-1 scripts: name, Web code syntax, and Default-mode value or alias target for all 346 variables. Aliases into linked libraries were resolved to their value.
- `import-figma.mjs` decides each variable's hook:
  - its code syntax
  - **or** the step in its name, when a ramp variable's syntax names another step or is missing
  - **or** the canonical hook, when the syntax is an SLDS alias
- It then compares Figma's resolved light value with Cosmos's and Lightning Blue's. The findings in §3 are the importer's own output.
- The re-pointed semantics (§5) were measured by resolving each Cosmos semantic to its ramp step.
- Counts re-tallied: 299 + 8 + 14 + 25 = 346, and 299 + 20 + 205 = 524.
